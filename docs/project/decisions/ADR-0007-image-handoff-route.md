# ADR-0007：图片交接的显示链路并入本插件，只读路由改收「会话 + 裸文件名」

状态：accepted

## 背景

纯文本模型（`inputModalities` 不含 `image`）会话里，内核会以 `MODEL_DOES_NOT_SUPPORT_IMAGES`
拒收带图片部件的消息，所以图片在发消息前被交接成工作区文件 `会话工作目录/.dsh-images/<sha256>.<ext>`，
消息里只留两行文本（人话行 + `[Image: source: <绝对路径>]` 机器行）。手机端有一条带鉴权的
REST 把它取回去显示；桌面 WebUI 此前没有对应能力 —— 交接消息在 WebUI 里只是一段文字，
用户看到的路径得自己去文件管理器找。

社区插件 `dsh-image-paths` 0.3.1 解决了 WebUI 这一半：一条宿主只读路由
（`/plugin/image-paths/raw?path=…&cwd=…`）+ 一个挂在 `conversation.chat.turnTail` 的浏览器图集，
只解析交接句式（用户消息里的行首标记）里的那个地址。用户的要求是把它并进本插件，
并在设置里加「识图路径」：路径可自定义，「当前默认」只读展示。

## 决策

1. **并入本插件**，不再依赖第二个插件的加载顺序，也不让同一张图被两个图集画两遍
   （两个插件的图集挂同一个 Turn 尾座位）。独立 `image-paths` 那一行应停用。
2. **只读路由换参数模型**：从 `path` + `cwd` 改为 `sessionId` + `name`（裸文件名）。
   目录由宿主按会话工作目录 + 当前识图路径推出，用的就是写盘那一套 `sessionWorkspaceDir()`。
   客户端因此**没有能力**表达「读哪个目录」—— 这条无令牌口子的攻击面被参数本身收掉了。
3. **识图路径成为设置项**：当前值存 `settings.image_handoff_subdir`（单段目录名，1-64 字符），
   出厂默认 `.dsh-images` 在设置页**只读**展示 —— 它是历史交接消息与下游工具的契约字面量，
   不跟着当前值走。写盘与两条读图路径都通过 getter 现读，改完立即生效，不需重启。
4. **信任模型沿用 image-paths 并加严**：回环 `Host`、拒绝跨站、文件名必须是内容哈希白名单、
   扩展名与魔术字节一致、32 MiB 上限；取不到一律 404 且不区分「会话不存在」与「文件不存在」。

## 理由

- 与写盘同源：交接的痛点是「写在哪、从哪读」两处漂移，参数里带 `cwd` 等于把这个判断交给客户端；
  由宿主按会话推目录，是唯一能保证两边永远一致的做法。
- `<img>` 带不了 `Authorization` 头，所以这条路由**无法**进 `/dsh-workspace-api` 前缀
  （那里每个请求都要设备令牌或回环管理身份）。它作为 `attachEmbeddedRoutes` 的第二个注册项存在，
  与 REST 各守各的信任模型。
- 座位必须是 `conversation.chat.turnTail`：Chat 节点座位会把自定义 kind 收进过程分组，
  standard 模式一折叠就是「DOM 里有、肉眼没有」。这一点上游 dsh-image-paths 已经踩过。
- 「当前默认」只读：它同时被历史会话回放、识图技能与手机端依赖，改它等于让旧消息里的路径
  指向一个不存在的目录。

## 后果

- 设置页导航多一个「识图」分区（根目录 / 远程访问 / 设备 / 识图 / 回收站 / 审计 / App 下载）。
- 独立 `image-paths` 插件与本插件**不能同时启用**（图会画两遍）；停用它不影响本插件的能力。
- 交接目录名一旦被改，**旧会话里已存在的图仍留在旧目录**（历史消息里的相对路径按当前设置解析）。
  改设置前已落的图若要再看，需要把它挪到新目录，或把设置改回去 —— 这是「一个会话目录一个当前值」
  的必然结果，设置页的只读默认栏就是给用户对照用的锚点。
- `/plugin/dsh-remote-bridge/raw` 的 `loopbackHost` 在把 GUI 绑到非回环网卡时必须同步放宽
  （与 `/plugin/image-paths/raw` 原本的约束相同）。

## 备选方案

- **保留 `path` + `cwd` 参数**：与上游插件完全一致，改动最小。否决 —— 无令牌路由却收客户端给的
  目录，等于把「能读哪个目录」的决定权交给调用方，只能事后用包含性校验补救；换成会话 + 裸文件名后，
  这个决定权在参数层面就不存在。
- **复用手机端那条带令牌的 `/api/v1/image-handoff`**：`<img>` 加不了请求头，不可行。
- **把图作为会话附件事件写进日志**：内核的持久化读取路径会拒绝树外事件类型（除非写方标
  `ignorable: true`，而 `Session.append` 设不了），会话格式会受影响。否决。
- **让用户自己配「当前默认」**：默认值是契约，不是偏好项。否决。
